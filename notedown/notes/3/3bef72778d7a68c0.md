<p>所有正常配置的 Linux 网卡（无论物理机、虚拟机还是容器内）都遵循同一套协议栈逻辑：</p><ol><li><p class="ds-markdown-paragraph"><strong>路由决策</strong></p><ul><li><p class="ds-markdown-paragraph">为网卡配置 IP 地址和子网掩码后，内核自动生成一条<strong>直连路由</strong>：目标网段＝该接口所在子网，无网关（或网关 <code>0.0.0.0</code>），出接口为该网卡。</p></li><li><p class="ds-markdown-paragraph">若还配置了默认网关，则同时生成一条<strong>默认路由</strong>：<code>0.0.0.0/0</code> 指向该网关 IP，出接口仍为该网卡。</p></li><li><p class="ds-markdown-paragraph"><strong>同子网通信</strong>：匹配直连路由 → 下一跳即目标本身。</p></li><li><p class="ds-markdown-paragraph"><strong>跨子网通信</strong>：匹配默认路由 → 下一跳为网关 IP。</p></li></ul></li><li><p class="ds-markdown-paragraph"><strong>ARP 解析与二层封装</strong></p><ul><li><p class="ds-markdown-paragraph">需要发数据包时，查 ARP 缓存获取下一跳 IP 对应的 MAC 地址。</p></li><li><p class="ds-markdown-paragraph">命中缓存：直接封装二层帧（目标 MAC＝下一跳 MAC，目标 IP 保持不变），从网卡发出。</p></li><li><p class="ds-markdown-paragraph">未命中：先广播 ARP 请求，得到应答后学习 MAC，再封装帧发送。</p></li><li><p class="ds-markdown-paragraph">同子网：下一跳 IP 就是目标 IP；跨子网：下一跳 IP 是网关 IP。</p></li></ul></li><li><p class="ds-markdown-paragraph"><strong>二层交换行为</strong></p><ul><li><p class="ds-markdown-paragraph">帧离开源主机网卡后进入直连的二层设备（交换机、Linux 网桥等）。</p></li><li><p class="ds-markdown-paragraph">二层设备<strong>只看目标 MAC</strong>：</p><ul><li><p class="ds-markdown-paragraph">广播/多播 → 泛洪到所有端口。</p></li><li><p class="ds-markdown-paragraph">单播且 MAC 在 CAM 表中 → 从对应端口转发。</p></li><li><p class="ds-markdown-paragraph">单播但 CAM 未命中 → 泛洪（未知单播）。</p></li></ul></li><li><p class="ds-markdown-paragraph">整个链路中，二层设备<strong>不解封 IP 头</strong>，只有目标主机或路由器才会解三层头处理。</p></li></ul></li><li><p class="ds-markdown-paragraph"><strong>跨网段路由转发</strong></p><ul><li><p class="ds-markdown-paragraph">路由器收到帧后，剥离二层头，检查目标 IP，查自身路由表，决定下一跳。</p></li><li><p class="ds-markdown-paragraph">重新封装新的二层头（新源/目标 MAC），从新接口发出。</p></li><li><p class="ds-markdown-paragraph">源主机包的目标 IP <strong>自始至终不变</strong>，每跳的目标 MAC 变化。</p></li></ul></li></ol><h2 style="line-height: 32px"><strong>Docker 容器网络与 Linux 网络栈的关系</strong></h2><p><strong>Docker 容器网络 = Linux 网络命名空间 + veth pair + 网桥 + 自动生成的标准路由配置 + 宿主机的 NAT 规则</strong>；</p><p>所有转发决策均遵循内核固有的路由/ARP/二层交换逻辑，容器内外协议栈行为完全一致。</p>
