<h3>基本概念</h3><ul><li><p>VxLan：虚拟可扩展局域网，Linux内核原生支持</p></li><li><p>VTEP（flannel.1）：VxLAN Tunnel End Point，内核态，负责数据封装、解包。内核flanneld进程。</p><blockquote><p>跟网桥的区别：</p><ul><li><p>内部维护FDB转发表，记录 Dst.VTEP.MAC 👉 Dst.eth0.IP 对应关系。</p></li><li><p>普通网桥（cni0\docker0）没有IP，只记录MAC和自身端口映射，但VxLAN.FDB记录IP</p></li></ul><p>跟flanneld进程的区别：</p><ul><li><p>S.flanneld封包、D.flannel解包的对象是<strong>UDP报文</strong>；S.VTEP封包、D.VTEP解包的对象，会在UDP报文内，多加 VTEP.MAC的二层帧 + VNI<strong>；</strong></p></li><li><p>flanneld工作在用户态，VTEP在内核态；</p></li><li><p>flanneld，通过目标主机IP + 目标flanneld进程Port送达对端；VTEP通过直连路由规则（flannel进程创建），找到D.容器IP所在的D.主机IP，再通过ARP获得D.主机MAC；</p></li></ul></blockquote></li><li><p>CNI网桥（cni0）: 取代docker0，本地容器的二层交换中心。</p></li></ul><p><strong>本质：利用VxLAN的隧道技术，构建Overlay网桥，承载三层的IP包；VxLAN底层隧道工作在L2，flannel-UDP模式底层隧道工作在L4（UDP）。</strong></p><p></p><p>关键信息：</p><ul><li><p>S.主机  路由  S.flannel.1（S.VTEP）</p><blockquote><p></p></blockquote></li><li><p>S.flannel.1 路由规则 获得 D.主机VTEP.IP(对端flannel.1设备的IP)，再结合ARP（<strong>新版本，由flannel进程将 每个VTEP对应的arp缓存，维护到每个节点上</strong>），获得D.VTEP的MAC</p><blockquote><p><span style="font-family: SFMono-Regular, Consolas, &quot;Liberation Mono&quot;, Menlo, Courier, monospace; color: rgb(102, 102, 102); font-size: 13px">Destination  Gateway    Genmask        Flags Metric Ref Use Iface</span></p><p><span style="font-family: SFMono-Regular, Consolas, &quot;Liberation Mono&quot;, Menlo, Courier, monospace; color: rgb(102, 102, 102); font-size: 13px">10.1.16.0    10.1.16.0  255.255.255.0  UG    0      0   0   flannel.1</span></p><p>目标容器所在的子网，网关IP := 该子网所在主机的VTEP.IP，最终封装后的二层数据帧，通过flannel.1发出。</p></blockquote><ul><li><p><code>内部二层数据帧</code>     =  <code>D.VTEP.MAC</code>+<code>原始IP包</code> ，不能在宿主机网络传输。</p></li><li><p><code>VxLAN数据帧</code>         =  <code>VNI默认=1</code>    +  <code>内部二层数据帧</code>  </p></li><li><p><code>宿主机网络UDP包</code>  =  `D.Port`</p><blockquote><p>FDB: 转发数据库（Forwarding Database）。flanneld进程维护，此时flannel.1x等同于网桥。</p><p></p><p>命令：bridge  fdb show flannel.1  | grep &lt;目标VTEP.MAC&gt;</p><p><span style="font-family: SFMono-Regular, Consolas, &quot;Liberation Mono&quot;, Menlo, Courier, monospace; color: rgb(102, 102, 102); font-size: 13px">目标VTEP.MAC dev flannel.1 dst 10.168.0.3 self permanent</span></p><p>发往 目标VTEP 的二层数据帧，将通过flannel.1设备发出，发往IP=10.168.0.3的主机。</p></blockquote></li></ul></li></ul><p></p><h3>过程</h3><p>案例：S.容器  on S.主机  访问👉  D.容器  on D.主机</p><p>原始报文：源.IP=S.容器.IP  目的.IP=D.容器.IP</p><h4>1. 源容器发出包过程</h4><ol><li><p>通过 VethPair 到达 S.主机 网络栈 的 cni0 网桥；</p><ol><li><p>通过 路由表  发往  S.VTEP 设备 flannel.1 ;</p><blockquote><p>目标                     网关                设备       标志</p><p>10.244.1.0/24 via 10.244.1.0 dev flannel.1 onlink</p><ul><li><p>flanneld预置；</p></li><li><p>将 目的.IP IN (D.主机.子网) 的流量，引向 S.VTEP <code>flannel.1</code> 且下一跳IP = 网关 = D.主机.VTEP.IP</p></li><li><p>两个关键信息：</p><ul><li><p>1. 报文发往VTEP设备</p></li><li><p>2. 目的IP = 网关IP = 目的.VTEP.IP</p></li></ul></li></ul></blockquote></li></ol></li><li><p>VTEP | 封装以太网头，目的IP + flannel预置的<strong>静态ARP表项</strong> 获取 <strong>D.VTEP.MAC </strong>;</p><blockquote><p>目的IP = D.主机.VTEP设备的IP地址</p><p>静态ARP记录：记录 所有 VTEP.IP 👉 VTEP.MAC 的 映射关系；</p><p>命令：ip  neigh  show  dev  flannel.1</p><p>&lt;目的.VTEP.IP&gt;  lladdr  &lt;目的.VTEP.MAC&gt;  PERMANENT</p></blockquote><p><code>内部数据帧</code>  = <code>源VTEP.MAC+目的.VTEP.MAC | 源.容器.IP+目的.容器.IP | 四层+...</code> </p></li><li><p>VTEP | 封装VxLAN头，VNI 默认值为 1</p><blockquote><p>VNI: VxLAN网络的标识符。</p></blockquote><p><code>VxLAN报文</code> = <code>VNI=1 | 内部数据帧</code> </p><blockquote><p>此时的报文是个二层报文，但无法在宿主机网络传输。</p><p>因为不知道目的.eth0物理网卡对应的IP，VTEP设备的IP没有网线连接，无法在宿主机网络传输。</p></blockquote></li><li><p>VTEP | 外层UDP+IP头，二层帧 over UDP，源.VTEP此处充当网桥。根据FDB获得D.VTEP.MAC 获得D.主机.IP</p><blockquote><p>静态FDB条目： flanneld进程预置，维护所有 VTEP.MAC 和 主机IP 的映射</p><p>命令：bridge  fdb  show  dev  flannel.1</p><p>&lt;目的.VTEP.MAC&gt;  dev  flannel.1  dst  &lt;D.主机.IP&gt;  self permanent</p></blockquote><p>D.端口号=8472（vxlan协议默认端口）</p><p><code>IP包</code>  = <code>S.主机.IP+D.主机.IP | S.主机.随机Port+D.主机.8472 | VxLAN报文</code></p></li><li><p>主机 | 二层封装，arp或路由表，获得 D.主机.IP的下一跳MAC（通常是网关MAC | arp中同一子网的）</p><blockquote><p>= Linux主机网络 = 源容器内</p><ul><li><p>同一子网，直连路由：下一跳MAC=arp获取的  D.主机.MAC， eth0 发出</p></li><li><p>不同子网，默认路由：下一跳MAC=网关MAC                           eth0 发出</p></li></ul></blockquote><p><code>二层数据帧</code> = <code>源.主机.MAC+D.主机.MAC | IP包</code> (同一子网)</p></li></ol><h4>2. 报文 👉 目的.容器</h4><ol><li><p>主机内核 | 一到4层解包，D.主机.eth0 接收，依次解出至UDP数据</p><blockquote><p>Linux主机网络</p><p>目的MAC == D.主机.eth0.MAC, 解2层包头，入 主机协议栈 - 路由层；</p><p>目的IP      == D.主机.eth0.IP, 解3层包头，入 主机协议栈 - 传输层；</p><p>目的端口  == 8472</p></blockquote><p><code>VxLAN报文</code> = <code>VNI=1 | 内部数据帧</code> </p><ol><li><p>主机内核 | VxLAN 解封装，根据VNI 入 <code>flannel.1</code></p><blockquote><p>内核解析VxLAN头，读取VNI</p><p>根据VNI，发送给VNI相同的VTEP设备，即 D.VTEP （flannel.0）</p></blockquote><p><code>内部数据帧</code>  = <code>源VTEP.MAC+目的.VTEP.MAC | IP包</code></p></li></ol></li><li><p>VTEP | 剥离 内层的层2头，获得容器.IP包</p><blockquote><p>目的MAC = 当前VTEP的MAC，解封2层包头，获得源容器发出的IP包。</p></blockquote><p><code>IP包</code>  = <code> 源.容器.IP+目的.容器.IP | 四层包</code></p></li><li><p>根据 路由，容器.IP包 👉 D.主机.cni0 网桥 发出</p><blockquote><p>路由示例：</p><p>&lt;D.容器子网&gt; dev cni0 proto kernel scope link src &lt;D.cni0.IP&gt;</p><p></p><p>cni0是二层设备，内核会封装MAC头，再从cni0发出</p><ol><li><p>arp请求|缓存(主机CAM表)，获得目标IP == <code>目的.容器.IP 的MAC地址，即 目的.容器.MAC</code></p></li></ol></blockquote><p><code>D.数据帧</code>  = <code>源.主机.cni0.MAC+目的.容器.eth0.MAC | IP包</code></p></li><li><p>cni0，通过 cni0.MAC地址表 发往cni0.veth，再通过VethPair 进入D.容器网络。 </p><p><code>D.数据帧</code>  D.容器网络栈，从层2，层层向上解封装。</p></li></ol><h3>关键</h3><ul><li><p><strong>VXLAN协议本身只定义了数据封装与FDB转发机制。</strong></p></li><li><p><strong>Flannel作为控制平面，负责利用etcd同步信息，并将这些信息具体化为宿主机上的路由、FDB和ARP表项。</strong></p><ul><li><p>路由：</p><ul><li><p>远端主机[1:N].子网，指向本机.flannel.1，网关=远端.主机.VTEP.IP</p></li></ul></li><li><p>ARP表：</p><ul><li><p>Flanneld静态配置，用于补充 <strong>VTEP间的邻居发现</strong></p></li><li><p>回答  "对端VTEP的MAC是什么？“</p></li><li><p>远端主机[1:N].VTEP.IP，对应的 远端主机[1:N].VTEP.MAC</p></li></ul></li><li><p>FDB表：</p><ul><li><p>Flannel静态配置，用于补充 <strong>VTEP设备所在主机 的 物理网卡IP</strong></p></li><li><p>"对端VTEP在哪台宿主机上？”</p></li><li><p>远端主机[1:N].VTEP.MAC，对应的 远端主机[1:N].eth0.IP（物理网卡IP）</p></li></ul></li></ul></li><li><p>cni0 负责所在节点的容器子网</p><ul><li><p>主机路由：</p><ul><li><p>直连路由，目标IP in (当前节点.容器子网) ，走cni0出去</p></li></ul></li><li><p>VethPair</p><ul><li><p>容器.网络NS   连接  cni0网桥</p></li></ul></li></ul></li><li><p>容器网络栈 == Linux主机网络栈：</p><ul><li><p>eth0网卡，IP、子网、默认网关，由此生成默认路由、直连路由。</p><ul><li><p>直连路由，cni0是网桥；</p></li><li><p>默认路由，cni0是网关，Dst.MAC := cni0.MAC</p></li></ul></li></ul></li><li><p>多增加封装大小：总共50字节。</p><ul><li><p>VTEP帧头：14字节</p></li><li><p>VxLAN头：8字节</p></li><li><p>UDP包头：8字节</p></li><li><p>IP包头：20字节</p></li></ul></li></ul>
