<h3>1. 基础概念</h3><ul><li><p>网络栈：进程发起和响应网络请求的基本环境，包括：网卡、回环设备、路由表、iptables规则。</p></li><li><p>期望状态：容器进程拥有自己独立的网络栈。</p></li></ul><h3>2. docker容器网络（VethPair + 网桥）</h3><ul><li><p>网线 VethPair：两个虚拟网卡对，从一个网卡发出的pack，可以直接出现在另一个网卡，即使两个网卡不在同一NS中（因此，常被用来连接不同NS的网线）。</p></li><li><p>网桥 docker0：根据mac将pack转发到自身不同的端口上。</p></li><li><p>示例：</p><ul><li><p>容器网络栈：</p><ul><li><p>网卡 eth0</p></li><li><p>路由（根据网卡配置，自动生成的默认路由、直连路由）：</p><ul><li><p>目标网络      网关            掩码              Flags    网卡</p></li><li><p>default         172.17.0.1    0.0.0.0           UG      eth0</p></li><li><p>172.17.0.0     0.0.0.0         255.255.0.0   U         eth0</p></li><li><p>路由1：默认路由，走eth0，目标MAC=网关172.17.0.1(docker0)的MAC</p></li><li><p>路由2：直连路由，同网段（目标网段 = 172.17.0.0/16） 的请求，走eth0，目标MAC从本机arp缓存查</p></li></ul></li></ul></li><li><p>Host网络栈：</p><ul><li><p>网卡 veth001</p><ul><li><p>容器内eth0的对端网卡</p></li></ul></li><li><p>网桥 docker0</p><ul><li><p>brctl show</p><ul><li><p>网桥名称  网桥ID                       STPenabled  网卡</p></li><li><p>docker0    8000.0242d8e4dfc1  no                veth001</p></li></ul></li></ul></li></ul></li><li><p>示例：容器A  ping  容器B</p><ul><li><p>1. 目标IP在 容器网段 172.17.0.0/16 ，因此匹配 路由2；</p><ul><li><p>路由规则含义：GW=0.0.0.0 表明 直连规则（凡匹配这个规则的IP包，都经过本机eth0网卡，经二层网络，直接发往目标主机）；</p></li></ul></li><li><p>2. 要二层到达容器B，需要获得容器B的MAC；</p><ul><li><p>2.1 容器A 通过本机eth0，发送ARP广播，通过目标IP，查找B的MAC；</p><ul><li><p>∵ eth0网卡是VethPair，eth0的另一端veth001位于宿主机HostNS，且被插在docker0网桥上；</p><blockquote><ul><li><p>虚拟网卡veth001 插 在网桥上，就会变为网桥的 从设备，剥夺调用网络协议栈处理数据包的资格；</p></li><li><p>虚拟网卡veth001 降级为 docker0上的一个 端口veth001；</p></li></ul></blockquote></li><li><p>端口veth001：网桥的端口，只能接收数据包；</p></li><li><p>端口veth001收到的数据包，转发还是丢弃，都由 docker0 决定。</p></li></ul></li><li><p>2.2 docker0收到ARP请求，将ARP广播给其他端口vethxx（插在docker0的其他虚拟网卡）；</p></li><li><p>2.3 容器B的eth0作为 某端口vethxx 的VethPair，收到广播ARP；</p></li><li><p>2.4 ∵ 目标IP == B.自身IP，容器B响应ARP请求，回复对应MAC给容器A；</p></li></ul></li><li><p>3. 容器A通过ARP请求获得容器B.MAC，便进行2层封包，发送数据包；</p></li><li><p>4. 数据包 经eth0-veth001， 到达docker0；</p><ul><li><p>4.1 docker0 根据 自身CAM 和 数据包中的目标MAC，查到对应端口veth0b</p></li><li><p>4.2 docker0 将数据包 发送给端口 veth0b；</p></li><li><p>4.3 数据包 再经过 veth0b-eth0 进入容器B 网络NS；</p><blockquote><p>veth001只是个端口，报文由docker处理。</p><p>docker0 = 二层交换机</p><p>二层交换机中，有CAM表（端口 - MAC地址 对应表）</p><p>转发端口 = 数据包.目标MAC + docker0.CAM表</p><p>转发端口，就是容器B在docker0上插的VethPair</p></blockquote></li></ul></li><li><p>5. 容器B.eth0网卡，出现流入数据包，容器B的网络协议栈处理数据包，并响应Pong 给容器A</p></li></ul></li></ul></li><li><p><strong>重点</strong></p><p>上面过程中，都有Linux的Netfilter参与，可以通过iptables的trace查看传输过程</p><blockquote><p>宿主机执行：</p><p>iptables -t raw -A OUTPUT         -p icmp -j TRACE</p><p>iptables -t raw -A PREROUTING -p icmp -j TRACE</p><p>之后，通过/var/log/syslog 查看数据包传输日志</p></blockquote></li></ul><h3>docker0既是网桥，也是三层接口</h3><ul><li><p>二层网桥：负责接入veth端口，以及端口直接的mac地址转发；</p></li><li><p>三层接口：拥有IP和MAC，作为宿主机的网卡，参与IP协议栈；</p></li></ul><p>报文如何分岔？</p><blockquote><p>容器网卡配置是手段，会最终生成 默认路由 + 直连路由。</p><ol><li><p>同网段进行二层封帧，直发eth0网卡（同网段，走直连路由）；</p></li><li><p>其他网段，走默认路由，即默认网关（不同网段，走默认路由）；</p></li></ol><p>多网卡，只为“主 上行接口” 设置默认网关</p></blockquote><ul><li><p>目标IP跟自身同网段，发ARP获取目标MAC，走容器间网络；</p></li><li><p>容器默认路由，下一跳是docker0的IP地址，即，目标IP=docker0的IP；</p><ul><li><p>arp获取docker0d的IP对应的MAC，docker0直接应答自己的MAC；</p></li><li><p>数据包目标MAC=docker0.mac</p></li></ul></li></ul><ol><li><p>目标MAC == docker0.mac</p><ol><li><p>发往宿主机的包，上交协议栈（入宿主机IP层，走路由、iptables等）；</p></li></ol></li><li><p>目标MAC == 网桥其他端口mac</p><ol><li><p>查CAM表，转发至对应端口，不进入宿主机IP层</p></li></ol></li><li><p>目标MAC == 广播、多播、CAM未命中的单播</p><ol><li><p>广播，目标MAC=全F（arp请求），docker会转发给所有端口veth</p></li><li><p>多播，IPv4(mDNS等)、IPv6(邻居发现)</p></li><li><p>CAM未命中的单播，容器arp缓存有效 但 网桥CAM数据丢失。</p></li></ol></li></ol><p><strong>docker0 只记录CAM（端口veth - MAC），arp缓存（IP - MAC）是容器、宿主机、三层路由器记录。一旦arp缓存失效，就一定会发arp请求，获取目标MAC。</strong></p><p></p><h3>同主：容器 访问 容器</h3><p><code>容器.路由规则</code> + <code>VethPair</code> +  <code>网桥(vethxxx降级为端口 + CAM根据mac查端口)</code>  </p><h3>容器 访问 其他宿主机</h3><p><code>容器.路由规则</code> + <code>VethPair</code> +  <code>网桥</code>  + <code>宿主机.路由规则</code> + <code>目标主机.eth0</code></p><h3>跨主：容器 访问 容器</h3><p>无法实现，引入 flannel-udp</p><h3></h3><p></p>
