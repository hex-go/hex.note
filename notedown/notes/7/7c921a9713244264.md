<h2>设计思想</h2><p>K8S在启动 infra容器后，可以直接调用CNI网络插件，为Infra容器的 网络NS 配置网络栈。</p><blockquote><p>网络栈：网卡、回环设备、路由表、iptables规则。</p></blockquote><h2>CNI部署、实现</h2><p>部署：安装K8S-CNI包，目的是<strong>在宿主机上，安装CNI插件所需的基础可执行文件</strong>。</p><blockquote><p>CNI的DaemonSet，挂载宿主机/opt/cni/bin，就实现了可执行文件安装。</p><p>flanneld在每个节点，生成对应的<strong>CNI配置文件（configmap）</strong></p><p></p><p>处理容器网络的逻辑，不在Kubelet主干代码，二是在CRI中（比如，dockershim加载CNI配置文件，配置文件的第一个插件，设置为默认插件）。</p></blockquote><p>CNI基础可执行文件，按功能分为三类：</p><ul><li><p>Main插件，用来<strong>创建网络设备</strong>（网桥、ipvlan、lo设备、macvlan、ptp、vlan）。</p></li><li><p>IPAM插件，负责<strong>分配IP地址</strong>（dhcp: 这个文件会向DHCP发请求；host-local: 使用预配置IP段进行分配）<strong>。</strong></p></li><li><p>CNI社区维护的内置插件。</p><ul><li><p>flannel：专门用于flannel项目；</p></li><li><p>tuning：通过sysctl 调整 网络设备 参数；</p></li><li><p>portmap：通过iptables 配置 端口映射；</p></li><li><p>bandwidth：使用 TokenBucketFiltre 进行限流；</p></li></ul></li></ul><h3>实现</h3><p>主要分为两部分：网络方案本身、网络方案对应的CNI插件。</p><ul><li><p>网络方案本身：flanneld进程中的逻辑。</p><ul><li><p>创建、配置VTEP；</p></li><li><p>配置节点路由、ARP静态记录、FDB表等</p></li></ul></li><li><p>CNI插件：配置Infra容器的网络栈，并连接到网桥cni0上。</p></li></ul><h3>工作原理</h3><p>kubelet创建Pod时：</p><ol><li><p>第一个，创建Infra容器，此时dockershim调用dockerAPI创建、启动Infra容器；</p></li><li><p>紧接着，执行 SetUpPod 方法。作用：</p><ol><li><p>为CNI插件准备参数；</p><ol><li><p>然后，调用 CNI插件(如：/opt/cni/bin/flannel) 为 Infra容器 配置网络；</p><blockquote><p>参数分为两部分：</p><ol><li><p>由 dockershim 设置的 <strong>一组CNI环境变量。</strong></p><p>其中最重要的ENV是 CNI_COMMAND，oneOf [ ADD, DEL ]</p><p>CNI插件只需要实现两个方法：ADD、DEL</p><ol><li><p>ADD：把容器添加到CNI网络；（网桥类，VethPair的方式，将容器插到cni0）</p><ol><li><p>参数（也在CNI环境变量中）：</p><ol><li><p>CNI_IFNAME（容器内网卡名称，eth0）</p></li><li><p>CNI_NETNS（Pod的网络NS文件 的路径，/proc/&lt;容器进程ID&gt;/ns/net）</p></li><li><p>CNI_CONTAINERID（容器ID）等</p></li><li><p>CNI_ARGS（以Key-Value格式，传递自定义信息）</p></li></ol></li></ol></li><li><p>DEL：把容器从CNI网络里移除；（网桥类，VethPair的方式，从cni0 拔 掉）</p></li></ol></li><li><p>dockershim 从<strong>CNI配置文件</strong>加载的，默认插件配置信息。</p><ol><li><p>NetworkConfiguration，以json格式，通过stdin方式，传递给cni插件</p><ol><li><p>flannel配置文件.delegate：CNI不会自己做事，二是调用delegate指定的CNI内置插件完成（对于flannel，调用delegate插件，就是CNI bridge插件）。</p></li></ol></li></ol></li></ol><p></p><p>ADD过程：</p><ul><li><p>FlannelCNI插件只做一件事，对传来的NetConfig进行补充（将delegate.type设置为bridge；delegate.ipam设置为host-local）</p></li><li><p>cni插件，根据delegate配置，调用 CNI-bridge插件（即，执行/opt/cni/bin/bridge），以stdin方式，</p><ul><li><p>1. CNI插件，stdin方式，将netConfig的delegate字段，传入CNI-bridge</p></li><li><p>2. CNI插件，以json格式，将netConfig的delegate字段，保存在/var/lib/cni/flannel目录（DEL操作使用）</p></li></ul></li><li><p>CNI-bridge，代表CNI插件，将容器加入cni0</p><ul><li><p>1. 检查cni0是否存在，不存在就创建</p><blockquote><p>ip link add cni0 type bridge</p><p>ip link set cni0 up</p></blockquote></li><li><p>通过Infra容器的NET_NS文件，进入 Infra容器.NET_NS 中，创建一对VethPair设备；</p></li><li><p>把VethPair的一端，移动到宿主机上。</p><blockquote><p>// 相当于，容器里执行以下命令：</p><p></p><p>// 创建<span style="font-family: SFMono-Regular, Consolas, &quot;Liberation Mono&quot;, Menlo, Courier, monospace; color: rgb(102, 102, 102); font-size: 13px">一对 VethPair 设备。其中一个叫作 eth0，另一个叫作 vethb4963f3</span></p><p>ip link add eth0 type veth peer name <span style="font-family: SFMono-Regular, Consolas, &quot;Liberation Mono&quot;, Menlo, Courier, monospace; color: rgb(102, 102, 102); font-size: 13px">vethb4963f3</span></p><p>// 启动 eth0 </p><p>ip link set eth0 up</p><p>// 将Veth Pair 设备的另一端（vethxxx）放到宿主机上（Host Namespace）</p><p>ip link set <span style="font-family: SFMono-Regular, Consolas, &quot;Liberation Mono&quot;, Menlo, Courier, monospace; color: rgb(102, 102, 102); font-size: 13px">vethb4963f3 netns $HOST_NS</span></p><p>// 通过Host Namespace，启动宿主机上<span style="font-family: SFMono-Regular, Consolas, &quot;Liberation Mono&quot;, Menlo, Courier, monospace; color: rgb(102, 102, 102); font-size: 13px">vethb4963f3</span></p><p>ip netns exec $<span style="font-family: SFMono-Regular, Consolas, &quot;Liberation Mono&quot;, Menlo, Courier, monospace; color: rgb(102, 102, 102); font-size: 13px">HOST_NS ip link set vethb4963f3 up</span></p></blockquote><p>上述操作也可以先在宿主机操作，再把VethPair对端（eth0）放入容器网络。原理相同，但CNI “<strong>反着</strong>” 来的原因：</p><blockquote><p>∵ 容器的NS可以直接通过NS文件拿到，但HostNamespaces是一个隐含在上下文的参数</p><p>∴ 先在容器NS操作，再反向操作HostNS对编程来说，更方便。</p></blockquote></li><li><p>将VethPath在主机网络的一端（<span style="font-family: SFMono-Regular, Consolas, &quot;Liberation Mono&quot;, Menlo, Courier, monospace; color: rgb(102, 102, 102); font-size: 13px">vethb4963f3</span>）连接到CNI网桥（cni0）</p><blockquote><p>等同于，在宿主机执行：</p><p>ip link set <span style="font-family: SFMono-Regular, Consolas, &quot;Liberation Mono&quot;, Menlo, Courier, monospace; color: rgb(102, 102, 102); font-size: 13px">vethb4963f3 master cni0</span></p></blockquote></li><li><p>CNI-bridge插件还会为 <code>vethb4963f3</code><span style="font-family: SFMono-Regular, Consolas, &quot;Liberation Mono&quot;, Menlo, Courier, monospace; color: rgb(102, 102, 102); font-size: 13px">设置 </span><code>Hairpin Mode(发夹模式）</code></p><blockquote><p>∵ 默认情况下，网桥设备不允许数据包从一个端口尽量，再从这个端口发出</p><p>Hairpin 可以取消这个限制。从而支持容器通过NAT（端口映射），自己访问自己的场景。</p><p></p><p>举例：-p: 8080:80</p><p>主机网卡会生成DNAT（目标地址转换），作用：</p><p>主机上，访问 ”&lt;HostIP&gt;:8080“时，iptables会把请求<strong>直接转发</strong>到"&lt;容器IP&gt;:80"</p><p>容器里，访问 ”&lt;HostIP&gt;:8080“时，IP包会先经过vethxxx和docker0网桥到达主机网络，再根据iptables的DNAT规则，重新回到docker0网桥，又通过相同端口进入容器里。这种情况下，vethxxx端口必须开启 Hairpin 模式。</p><p></p><p><span style="font-family: &quot;PingFang SC&quot;, &quot;Lantinghei SC&quot;, &quot;Microsoft Yahei&quot;, &quot;Hiragino Sans GB&quot;, &quot;Microsoft Sans Serif&quot;, &quot;WenQuanYi Micro Hei&quot;, Helvetica, sans-serif; color: rgb(53, 53, 53); font-size: 17px">hairpinMode=true。Pod 才可以通过它自己的 Service 访问到自己。</span></p></blockquote></li><li><p>CNI- bridge插件，配置容器eth0网卡。</p><blockquote><ol><li><p>调用CNI-ipam插件，从ipam.subnet规定的网段，为容器分配一个可用IP</p></li><li><p>CNI-bridge插件把ip、网关(cni0的ip)、子网掩码设置到eth0网卡。</p><blockquote><p>相当于，容器里执行：</p><p>ip addr add 10.244.0.2/24 dev eth0</p><p>ip route add default via 10.244.0.1 dev eth0</p></blockquote></li></ol></blockquote></li><li><p>CNI-bridge插件，为CNI网桥(cni0)设置IP</p><blockquote><p>ip addr add 10.244.0.1/24 dev cni0</p></blockquote></li></ul></li><li><p>CNI把容器IP地址等信息，返回dockershim，然后被kubelet添加到pod.status</p></li></ul></blockquote></li></ol></li></ol></li></ol>
